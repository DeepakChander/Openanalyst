## Anti-Patterns

### Premature Optimization
Optimizing before the demo works
**Why it's bad:** Get it running first, then optimize byte by byte
**Instead:** Develop with readable code, then minify at the end

### Ignoring GPU Differences
Testing only on your development machine
**Why it's bad:** Different GPUs handle edge cases differently
**Instead:** Test on multiple GPU vendors (NVIDIA, AMD, Intel) before party

### No Fallback Rendering
Assuming WebGL2 or specific extensions
**Why it's bad:** Competition machine might not support your features
**Instead:** Have WebGL1 fallback or graceful degradation

### Hardcoded Resolution
Assuming 1920x1080 or specific resolution
**Why it's bad:** Demo compo machines vary; big screen might be different
**Instead:** Use canvas dimensions dynamically, handle aspect ratios

### Framerate-Dependent Animation
Animation speed tied to frame rate
**Why it's bad:** Fast machine = fast demo, slow machine = slow demo
**Instead:** Use deltaTime or real time for all animations

### Ignoring Audio Sync
Visuals not synchronized to music
**Why it's bad:** Demo feels disconnected, loses emotional impact
**Instead:** Derive visual parameters from audio analysis or shared timeline
