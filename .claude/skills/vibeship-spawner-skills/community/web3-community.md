```
## DAO Community Governance

### Governance Structure
| Type | Best For |
|------|----------|
| Token voting | Large decisions |
| Delegate system | Participation at scale |
| Multisig | Treasury, execution |
| Working groups | Day-to-day operations |

### Proposal Process
1. Temp check (gauge interest)
2. RFC (request for comments)
3. Formal proposal
4. Voting period
5. Execution

### Preventing Governance Fatigue
- Don't vote on everything
- Delegate system
- Clear scope for each level
- Compensate active participants
- Async-friendly processes

### Governance Attacks
| Attack | Prevention |
|--------|------------|
| Vote buying | Time-locked voting |
| Flash loans | Snapshot at proposal |
| Plutocracy | Quadratic voting |
| Apathy | Quorum requirements |
```

## Anti-Patterns

### Promising Price
Making price predictions or promises
**Why it's bad:** Securities law issues.
Attracts wrong crowd.
Impossible to deliver.
Destroys trust when price drops.


### Rug Pull Patterns
Behaviors that look like exit scam setup
**Why it's bad:** Even unintentional, these destroy trust.
Community assumes the worst.
Hard to recover from perception.


### Mercenary Community
Community only there for gains
**Why it's bad:** Leaves when price drops.
No genuine connection.
Toxic culture.
No long-term value.

### [CRITICAL] Scammers targeting your community

**Situation:** Community members losing funds to scams

**Why it happens:**
Web3 communities are scammer magnets.
DMs, fake airdrops, phishing sites.
Your community's reputation suffers.


**Solution:**
```
## Anti-Scam Protocols

### Education (Constant)
- Pin: "We will NEVER DM you first"
- Pin: "We will NEVER ask for seed phrase"
- Regular reminders
- Scam example screenshots

### Technical Prevention
| Platform | Tools |
|----------|-------|
| Discord | Wick, Carl-bot, disable DMs |
| Telegram | Anti-spam bots, slow mode |
| Twitter | Verified checkmark |

### When Scam Happens
1. Warn community immediately
2. Document the scam
3. Report to platform
4. Share on Twitter (awareness)
5. Support affected members
6. Never blame victims

### Proactive Measures
- Claim similar domain names
- Monitor for fake accounts
- Trademark protection
- Regular security reminders

```

**Symptoms:**
- I got a DM from admin
- Phishing links shared
- Fake token launches
- Impersonator accounts

### [CRITICAL] Malicious actors exploit governance

**Situation:** Bad actors manipulate DAO votes

**Why it happens:**
Token-weighted voting is exploitable.
Flash loan attacks.
Vote buying.
Coordinated action.


**Solution:**
```
## Governance Security

### Prevention
- Snapshot voting (block before proposal)
- Time-locked tokens
- Quorum requirements
- Proposal thresholds
- Delegate system

### Monitoring
- Watch large token movements
- New wallets accumulating
- Unusual proposal patterns
- Coordinated voting

### Response
1. Pause governance if possible
2. Investigate the attack
3. Community communication
4. Fix vulnerability
5. Consider rollback if needed

### Healthy Governance
- Multiple safeguards
- Not everything is voteable
- Emergency multisig
- Transparent processes

```

**Symptoms:**
- Unusual proposals
- Large token movements
- Coordinated voting
- Hostile takeover attempts

### [CRITICAL] Regulatory action against project/community

**Why it happens:**
Unclear regulatory environment.
Securities law questions.
Jurisdiction issues.


**Solution:**
```
## Regulatory Preparedness

- Legal review of token structure
- Avoid securities language
- No profit promises
- Geographic restrictions
- Clear terms of service

### Communication Don'ts
- Don't promise returns
- Don't call tokens investments
- Don't guarantee price
- Don't compare to stocks

### If Contacted by Regulators
1. Engage legal counsel immediately
2. Don't destroy evidence
3. Cooperate appropriately
4. Communicate carefully to community
5. Don't speculate publicly

### Community Communication
- Be factual
- Don't spread FUD
- Follow legal guidance
- Maintain transparency within limits
```
